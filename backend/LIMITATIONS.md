# Limitations and their management

This register connects known restrictions to evidence and implemented responses. Revisit it alongside operational exports and real participant testing; passing software tests alone does not establish model quality or usability.

| Limitation | Evidence to present | Implemented management | Remaining restriction |
|---|---|---|---|
| Generated rooms can change geometry, windows or furniture | Fabryzzio's transfer review; permitted original/generated examples; recorded rejection counts/reasons in the application | Original-photo regeneration, preservation instructions, preview, acceptance/rejection and feedback | Human review is required; no measured dimensions or structural guarantee. |
| Custom Luxury is not proven superior | Training/evaluation branch: six transfer rooms, two seeds, one reviewer; distinguish preference from geometry and independent rooms from repeated seeds | Both custom and original adapters available, explicit choice, immutable model settings/hash and version history | Small, hotel-heavy sample; first-review acceptance is preference evidence, not proof of generalization. |
| GPU work takes time and one worker serializes jobs | Recorded smoke timings/VRAM; new queue-wait/processing/turnaround samples and queued-job counts | Durable queue, polling, progress, recoverable errors, expiring leases and fenced publication | Kaggle quota/startup/tunnel availability and queueing constrain demos; no production SLA or load-capacity claim. |
| Temporary inference can stop or lose a lease | Interrupted-job regressions, job-attempt/recovery counts and notebook-restart tests | Supabase persistence, retryable jobs, pinned settings, stale-lease rejection | Recovery can repeat computation; wall time includes recovery gaps and final-attempt samples omit interrupted GPU work. |
| Storage/network operations can fail | Job errors and technical retry counts; storage-failure/idempotency/deletion tests | Previous versions retained during failed replacements, retry keys, staged-file cleanup and deferred rechecks | Timings/success reports cover persisted jobs; pre-persistence upload/network failures are not fully instrumented. |
| Qwen can return filler, invalid structure or ungrounded content | Invalid/stale-summary regressions, saved summary comparisons and stage timings | Recorded decisions/reasons rendered directly, ID/excerpt validation, one retry and revision checks | Description accuracy still needs image review; validation of quoted text does not prove every visual claim. |
| Bedroom classification can be uncertain | Test cases for wrong-room/uncertain inputs; session statuses and expected-input-rejection counts | Bedroom-only workflow, uncertain-input confirmation, image type/size/pixel caps | A confirmation is a user assertion; classifier accuracy has not been established on a broad labelled sample. |
| Required weights must be mounted in the active Kaggle editor | Both saved dataset attachments verified; preflight tests for missing/duplicate/wrong-hash files | Explicit Add Input instructions and filename/hash verification before loading models | An older editor draft/session can retain old inputs; reload/add the dataset and restart the session. |
| Reports have limited coverage and sample sizes | Exported cohort metadata, sample counts, legacy/missing/truncated counters and actual participation record | Zero-event denominators, separate action types, immutable model attribution, no exported identifiers/text | Deleted records disappear; owner accounts are not independently verified people; no small-sample causal or population claim. |

The team should export the measurements needed for grading before the documented purge. Training, improving the LoRA, adding spatial controls and implementing a production monitoring platform are separate work; none is claimed as a completed mitigation here.
